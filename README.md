# 不熟局 BU SHU

广州大学城的盲盒组局：不熟的人凑一桌，一起干件具体的小事。

- **线上地址**：https://whatif146.github.io/bushu/
- **代码仓库**：https://github.com/whatif146/bushu
- **技术栈**：React 18 + Vite 5，手写 CSS（无 UI 框架），数据在 localStorage

广州大学城（小谷围岛）校园盲盒组局平台。选一场局，填一份问卷，AI 在幕后把合适的人凑成一桌；**出发前 30 分钟才知道去哪，见面之后它就不出现了。**

- 站点类型：工具站 + 落地页打法，核心转化动作只有一个：**提交报名**
- 技术栈：Vite 5 + React 18，手写 hash 路由，**零 UI 框架依赖**；图片 2 张（Wikimedia CC BY-SA）、字体 3 族（思源宋体/黑体 + JetBrains Mono，Google Fonts CDN）
- 数据：浏览器 `localStorage` 单键 `bushu.v1`（演示用假数据，不连接任何后端）
- 视觉：纸（`#F2EDE3`）+ 墨（`#17140F`）+ 朱红（`#D8351E` 家族），圆角全局 0，硬边 + 硬影

## 路由

| 路径 | 页面 | 说明 |
|---|---|---|
| `#/` | 落地页 | 9 个区块：Hero / 朱红跑马灯 / 16 类局 / 一局怎么发生 / 本周局 / 不打保票 / FAQ / Footer |
| `#/join` | 报名问卷 | 7 步，Step 4 按局型出不同题目；`#/join?type=dinner` 可预选 |
| `#/me` | 我的局 | 报名 / 匹配中 / 已揭晓 / 进行中 / 已结束 五种状态 |
| `#/table/:groupId` | 同组速览 | 匹配理由、同组的人、物料预览、集合信息（含场地锁）、打印 |
| `#/live/:groupId` | 现场引导 | 全屏无导航；话题卡牌 / 打卡表 / 赛制 / 课程表四种形态 |
| `#/recap/:groupId` | 回顾 | 一句话总结、金句投票、评价、想续桌 |
| `#/admin/:tab` | 后台 | 概览 / 匹配工作台 / 活动类型 / 场地库 / 题库 / 物料 / 任务 |

前台页面组件**不接收 props**，自己从 `useRoute()` 取参数、从 `api.js` 取数据。

## 分层（重要）

```
页面 src/pages/*.jsx
  ↓ 只调
src/lib/api.js        数据入口 + 脱敏 + 场地锁判断
  ↓
src/lib/store.js      localStorage / 种子展开 / 全部写操作 + 订阅
  ↓
src/data/*.js         16 类局、15 个场地、42 个用户、11 场局、题库
```

页面里出现 `localStorage` 即为违规（当前为 0 处，仅注释提及）。同组速览只下发 `majorBroad`（12 类宽专业），不下发画像七维数值与问卷原文。

## 匹配引擎（`src/lib/match.js`）

四套打分函数，权重合计恒为 1（模块加载时自检，不平即抛错）：

| 局型 | 主要维度 | 关键约束 |
|---|---|---|
| social | 性格互补 .30 / 话题重合 .22 / 表达节奏 .18 | 组内需有人开口（表达欲 ≥0.60） |
| buddy | 目标一致 .32 / 作息重合 .24 / 强度相当 .16 | 可用时段交集 ≥2 |
| competitive | 段位接近 .38 / 争胜心 .20 / 分队均衡 .16 | 段位跨度 ≤1 档；羽毛球、桌球单对分 ≥0.40，篮球、爬山放宽到 0.25；开黑局用目标强度 0.65 当准入门槛，人不够时自动降级并在 notes 写明 |
| skill | 技能互补 .34 / 教愿意愿 .20 / 能讲清楚 .16 | 教 ≠ 学 |

- **确定性**：不用 `Math.random`，用 `mulberry32(hash(eventId))`，同一输入必须得到同一分组（后台「换人预演」要对得上账）。
- **可解释**：`explainScore()` 把加权项拆开，后台「为什么这样分」直接可视化。
- **可拒绝**：`QUALITY_FLOOR = 0.62`，达不到就散组进候补，不硬凑。
- 自测：`node scripts/match-selftest.mjs`，57 项断言全过（含禁语扫描、跨组换人、池级降级）。

## 物料（`src/lib/materials.js`）

按局型生成四种：`topicCards` 话题卡牌 / `checkinSheet` 打卡表 / `tournament` 赛制 / `skillSchedule` 互教课程表。
只产出结构化数据，打印版式由页面按 `printSheet` 渲染，`@media print` 下输出 A4 单页。话题卡只印当场要用的 12 张（破冰 4 / 兴趣 5 / 观点 3），页脚注明全副张数与「其余在后台题库加印」——印的是今晚这桌的牌，不是题库。

`checkinCode` **不出现在任何面向学员的界面**，只在打印纸页眉与后台。

## 演示怎么走（5 分钟）

1. `#/` 看落地页 → 点「报一局」进问卷，7 步填完提交
2. `#/me` 顶部「切换演示身份」可切成另外两位学生或管理员
3. 以管理员进 `#/admin/match`：选场次 → 开始匹配 → 展开「为什么这样分」→ 锁定分组
4. 回 `#/me` 看已揭晓的组 → `#/table/g_01` 看同组与物料 → 打印预览
5. 到 `#/live/g_01` 用卡牌，最后 `#/recap/g_01` 看回顾

## 2026-10-20 视觉与交互调整（青春化）

整体是「保留识别度、提高活力」的一次 Preserve 级改造，没动路由、字段、状态机与文案口径。

**删掉的**
- 首屏底部 `XIAOGUWEI ISLAND · GUANGZHOU`：纯占位，模板感最重
- 各区块的英文小标（`5 STEPS` / `THIS WEEK` / `WHAT WE PROMISE` / `FAQ`）与 `01–08` 节号：与正文步骤号撞车，也让页面像排版练习
- 首屏说明里重复的「10 所学校」（上方 meta 已有）
- 问卷的「还剩 6 步」：催人，且与「第 1 / 7 步」重复
- 后台「质量线 0.62（§6.4 C11）」：规范编号不该出现在运营界面
- 竖排标题末尾的句号（只在视觉上隐藏，DOM 保留，读屏仍读全句）

**加上的**
- 荧光笔色 `--mark`（≤5% 面积）：只用来划重点，不参与结构
- 贴纸：本周局第一张卡上的「还剩 n 位 / 已满」，桌面端显示
- 主推卡：本周局第一张横跨两列、加大字号与硬影
- 错落：五步改成台阶式下沉，类型带第一张加宽 1.6 倍
- 交互：类型带支持滚轮横推与鼠标拖拽（拖过 6px 不算点击）、问卷输入框回车即下一步、按钮箭头 hover 前移

**修掉的毛病**
- 移动端底部固定 CTA 的箭头 SVG 没有尺寸约束，撑成 335×335 盖住整条按钮
- 类型卡汉字水印与局名抢位置 → 改为右下角 8% 水印
- 跑马灯两端被切一半像坏了 → 加渐隐遮罩，分隔符从 `·` 改成 `／`（局名里本来就有 `·`）

## 质感层 `src/styles/refine.css`（2026-10-20 第二轮）

页面样式之后最后引入的一层，只做收敛，不加新元素。它把「贴纸拼贴」调成「印刷品」：

- **颜色回到三色**：去掉荧光绿，划重点改成文字下的一道浅朱红下标线
- **线**：2px 实线与 4px 硬投影全部换 1px 发丝线（`rgba(23,20,15,.14)`），阴影只留给浮层
- **字**：中文标题不再压字距（-0.012em），正文行高 1.78，`text-wrap: pretty`
- **留白**：桌面区块间距 128 → 152，墨底区 160 → 176
- **首屏**：竖排 8.2vh、列距 44px，数字沉到首屏底部与左侧长标题成对角
- **动效**：去掉位移弹跳，只换色，240ms `cubic-bezier(.22,.61,.36,1)`
- **卡片**：主推局卡改成墨底纸字（比加投影更能表达「这一张重要」），贴纸不再旋转

注意：改这一层要同时看 `landing.css` 里的同名规则，后写的赢；`npm run dev` 若没生效，重启（新增文件有时不被旧进程的 watcher 捕获）。

## 字体系统（2026-10-21）

| 用途 | 字体 | 为什么 |
|---|---|---|
| 标题（H1/H2/H3、竖排、局名） | **Noto Serif SC**（思源宋体）500/600 | 中文标题的「骨架」来自宋体；系统黑体再调字距也只能做到干净 |
| 正文与 UI | **Noto Sans SC**（思源黑体）400/500/700 | 跨平台一致，比 Windows 默认雅黑更干净 |
| 数字 / 编号 | 同上 Serif，`font-variant-numeric: lining-nums tabular-nums` | 等宽数字，成列时对得齐 |
| 标签 / 注脚 / 状态 | **JetBrains Mono** 400/500 | 软件感来自这些小字，不是来自标题 |

三条配套规则（写在 `refine.css` §16）：

1. 宋体标题字重降到 600——用 800 会把笔画糊成一团；
2. 中文标题字距回 0（黑体时代压到 -0.03em 是错的）；
3. 正文字号抬到 16.5px / 行高 1.72。

⚠️ **字体走 Google Fonts CDN，中国大陆访问可能很慢或被阻断**。正式对外前建议改成自托管：用 `fontmin`/`subset-font` 按站内实际用字裁出子集（标题字重只保留 3000 字左右，体积可降到 200–400KB），放进 `public/fonts/` 用 `@font-face` 引入。

## 可玩性：开一个（2026-10-21）

参考了 Awwwards 2026 获奖站的三种做法——「单一互动组件贯穿全站」（Telha Clarke）、「把品牌动作做成玩法」（Max Mara 字谜）、「有音画反馈的角色」（Ribbit）——本站对应的是**把「盲盒」从比喻变成动作**：

- 组件 `src/components/BlindBox.jsx`，落地页实拍条之后
- 点一下：盒盖翻开（`rotateX(-118deg)`），一张卡从盒里升起来
- 卡片内容真随机：16 种局里抽一种 + `src/data/questions.js` 里的破冰题库抽一道；编号 `NO.09 / 16`
- 抽到不想去的点「再开一个」；开满 3 次会出现「开够了，直接看这周的局」
- 卡片底部写明「开盒只是随机看看，不代表还有位置」——**不把随机当成库存**

配套的两处手感：

- 五步随滚动逐条点亮（IntersectionObserver，一次性；1.5 秒兜底，避免停在半透明）
- 所有 3D 与过渡遵守 `prefers-reduced-motion`

**没做的**：音效（会打扰、且需要开关）、假数据抽奖（会骗人）、下拉小游戏（与转化无关）。

## 现场抽卡（2026-10-21）

`#/live/:groupId` 的话题卡从「按顺序讲」改成「真的抽」：

- **按组洗牌**：`shuffleSeeded(deck, groupId)`——每桌牌序不同，同一桌刷新后顺序不变（种子由组 id 生成，可复现）
- **牌背朝上**：抽到的牌先盖着（黑底竖排「不熟局」+ `NO.01`），点一下才翻面
- **翻开的牌**：题面 + 一句提示 + 「由 X 先答」（原来「由谁来答」的背面信息合并进来）
- **牌堆有厚度**：卡片下方三层纸边，配「还剩 N 张」
- **换牌动画**：`key` 变化触发 `deckIn`（上浮 + 轻微旋转，320ms），不设 fill mode，翻面的 `rotateY` 不受影响

测试方式（页面有时间闸门）：改 localStorage 里 `bushu.v1` 的 `groups[g_00].status='ongoing'` 并把场次时间拉到当下，重载后进入。

## 已知限制（本期不做）

- 没有后端：报名、匹配结果都存在浏览器里，换设备即清空；**两台手机不会看到同一桌**
- 无真实登录：`#/me` 底部与后台顶栏是「切换演示身份」，不是鉴权
- SEO：hash 路由下各页不是独立 URL，爬虫只看到首页；改 History API 属 P1
- 签到码在 App 内不显示，只能从打印纸或找负责人拿；弱签到（我到了）单独计数，不假装是强证明
- 种子日期是固定的（10-17 ~ 10-28）。种子重建时会把未开始场次的报名截止/匹配/解锁时间按「开始前 6h / 4h / 30min」重算，所以随时打开都能报名；但**场次本身过期后需要改日期**
- 合影上传、真实二维码、支付、通知推送都不在本期

## 怎么分享出去（以及一个必须说清的限制）

**能分享的**：`npm run build` 之后把 `dist/` 丢到任何静态托管（EdgeOne Pages / Vercel / 校园服务器都行），拿到一个链接就能发群、发公众号。页脚有「复制链接 / 发给同学」，手机上是系统分享面板。`public/og.png` 是 1200×630 的分享卡，微信抓图用。

**上线后必做一步**：把 `index.html` 里的 `og:image` 从 `./og.png` 改成绝对地址 `https://你的域名/og.png`，否则微信不会出图。

**必须说清的限制**：现在报名数据只存在**访问者自己的浏览器**（localStorage）。所以：
- 链接可以发，别人能看到站、能填问卷、能看到自己那桌；
- 但你**收不到**他们的报名，两台手机也不会进同一桌。

要真的「用起来」，必须补一层后端，三条路按成本排序：

| 方案 | 做什么 | 成本 |
|---|---|---|
| 云开发（CloudBase / Supabase） | 报名、分组、签到存云数据库，加一个登录 | 半天到一天，官方连接器可用 |
| 轻后端 | 只做一个 `POST /applications` + 后台列表，其余仍在前端 | 半天 |
| 合规兜底 | 报名按钮跳到腾讯问卷/飞书表单，站只做展示 | 半小时，但「我的局」就断了 |

现在这版适合**演示和收集意向**，不适合直接当成报名系统对外用。
