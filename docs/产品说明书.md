# 不熟局 · 产品说明书

**版本** v1.0（2026-10-21）　**形态** Web 应用（移动优先）　**线上** https://whatif146.github.io/bushu/

---

## 1. 一页纸概要

**一句话**：把「想认识人但不想硬聊」的大学生，按问卷配成一桌 4–8 人，一起干一件具体的小事。

| 项目 | 内容 |
|---|---|
| 面向 | 广州大学城 10 所高校的在校生，尤其是一个人吃饭、一个人自习的那批 |
| 核心动作 | 只有一个：**提交报名**。其余所有页面都为它服务 |
| 关键差异 | 报名不看脸、不看照片，看你怎么说话；**出发前 30 分钟才知道去哪** |
| 规模 | 16 类局、每桌 3–8 人、单场最多开多桌 |
| 不做 | 不承诺交到朋友、不做颜值匹配、不做聊天、不卖货 |
| 当前状态 | **前端演示版**：全部流程可点通，数据存在访客本机（详见 §11） |

---

## 2. 要解决的问题

大学城的社交困境不是「没有活动」，而是三件事同时成立：

1. **活动太多，但都要求你先表现得有趣**——海报、群公告、自我介绍，第一步就把不擅长开场的人筛掉了。
2. **加了好友，却没有下一步**——活动结束各回各校，关系停在「点赞」。
3. **一个人做事的门槛很低，找人一起做反而很高**——自习、夜跑、看展，本来就是一个人也行，但一个人做久了会闷。

所以产品要解的不是「帮你认识人」，而是「**让你不需要表演，也能坐到一桌人中间**」。

## 3. 产品原则

这五条是设计与开发时的硬约束，不是口号。

| 原则 | 具体表现 | 反例（我们不做） |
|---|---|---|
| **不承诺结果** | 全站写三遍「不承诺任何结果」；匹配理由只陈述事实，不写「正好有人能接住你」 | 「保证你交到 3 个朋友」 |
| **盲盒只在场地** | 组已成立、出发前 30 分钟才解锁具体店名；在此之前界面只到「片区」 | 提前放店名换报名量 |
| **不看脸** | 无头像上传、无照片、无性别筛选（性别比例只做兜底校验） | 颜值卡片、照片墙 |
| **AI 退场** | 匹配完成后，AI 不在任何用户页面出现；现场页不出现推荐、评价、分享、slogan | 全程 AI 助手陪聊 |
| **不用力过猛** | 文案短、句子停得住；不用感叹号、不用「宝子」「家人」 | 鸡血式运营话术 |

## 4. 用户旅程

| 步 | 用户此刻的问题 | 系统在做什么 | 页面 |
|---|---|---|---|
| 1 挑局 | 「有什么局？哪个适合我？」 | 展示 16 类局 + 本周 8 场，标出还剩几位 | `#/` 落地页 |
| 2 填问卷 | 「要填多少？会不会很麻烦？」 | 7 步、每步 1–2 个问题，可随时退出并保留草稿 | `#/join` |
| 3 等匹配 | 「我填的东西有人看吗？」 | 截止后统一排桌，未成桌进候补并说明原因 | `#/me` |
| 4 现场 | 「到了找谁？聊什么？」 | 签到码 + 抽卡 + 打卡表；场地与同桌在解锁后可见 | `#/table/:id`、`#/live/:id` |
| 5 回顾 | 「这局到底怎么样？」 | 散场回顾、谁来了、下次还来吗 | `#/recap/:id` |

**关键的「不做」**：报名之后没有聊天功能。理由：**先在现实里见，再决定要不要加微信**；给一个聊天框，等于把「不敢开口」的问题挪到线上继续。

## 5. 功能说明

### 5.1 落地页 `#/`

- 竖排主标题「不熟的人，一起干件小事」——竖排是中文书写的原生形态，也是本站唯一的视觉签名
- 首屏右侧三格实时数：本周场次、在校报名、一桌几人（取 16 类局的人数区间，不写死）
- **开一个盲盒**：随机抽一种局 + 一道破冰题，可反复开；开满 3 次给「直接看这周的局」（详见 §5.8）
- 16 类局横向带：可滚轮横推、可拖拽；第一张加宽当封面
- 本周开的局：第一张为主推卡（墨底 + 单色湖景照），其余为常规卡
- 一张实拍横幅（南亭村口），把「这是真人真地方」说清楚
- 五步流程、不承诺区、FAQ、分享条

### 5.2 报名问卷 `#/join`

七步：校园认证 → 你是谁 → 想干什么 → 说三句 → 补问 → 最后两个 → 确认。

- 每一步独立校验，错误就地提示，不整表打回
- 输入框按回车即下一步；多行输入、下拉、按钮保持原行为
- 「说三句」是核心：自我介绍、想认识什么样的人、最近的状态，各 10 字以上
- 可勾 1–3 类兴趣局型，决定你能被排进哪些桌
- 全程可退出，草稿保留在本机

### 5.3 我的局 `#/me`

- 报名状态：待匹配 / 已进桌 / 候补（附候补位次与原因）/ 已取消
- 分桌之前可修改答案，改完需重新提交
- 历史记录：参加过的局、当时的同桌、回顾入口

### 5.4 同组页 `#/table/:id`

六个区块：桌头（组号/时间/人数）、氛围与理由、同组的人、共同话题、集合信息、物料预览。

- **场地锁**：未到解锁时间，场地名不进 DOM（不是隐藏，是后端字段置空）
- 同组卡不显示 traits 数值、精确专业、手机号、别人的匹配理由
- 打印：`@media print` 输出 A4 单页（详见 §5.7）

### 5.5 现场页 `#/live/:id`

移动优先、整页不滚动、一屏一张卡。

- **抽卡**：牌堆按组洗牌（同组刷新顺序不变），牌背朝上，点一下翻面看题
- 翻开的牌同时给出「由谁先答」，避免一桌人互相看
- 底部一行「还剩 N 张」，抽完自动收尾
- 签到：6 位数字码，输入即打卡
- 不适随时可点「不舒服就点这里」，触发安全流程

### 5.6 散场回顾 `#/recap/:id`

- 谁来了、谁没来、这桌聊了什么
- 「下次还来吗」的一键投票，决定是否为你开新一轮

### 5.7 打印（同组页内）

- 触发后才挂载打印件——**签到码平时不在 DOM 里**
- A4 单页：朱红页眉（活动/组号/签到码）、左栏话题卡、右栏同桌身份卡、页脚规则与页码
- 话题卡只印当场要用的 12 张（破冰 4 / 兴趣 5 / 观点 3），页脚注明全副张数与「其余在后台加印」

### 5.8 开一个盲盒（落地页）

把「盲盒」从比喻变成动作：点击 → 盒盖翻开 → 卡片升起 → 随机一种局 + 一道破冰题。

- 随机来源是真数据：16 类局 × 题库破冰题
- 卡上明确写「开盒只是随机看看，不代表还有位置」——**不把随机当成库存**
- 开满 3 次出现「开够了，直接看这周的局」，给玩家一个下台阶

## 6. 匹配机制

### 6.1 可复现

同一份输入，跑两次结果逐字一致（用固定种子的伪随机）。这不是洁癖：**不可复现的匹配，无法被人质疑，也无法被修**。

### 6.2 四道闸门

| 闸门 | 内容 | 不通过时 |
|---|---|---|
| 硬条件 | 性别比例兜底、单人报名上限、时间冲突 | 直接不进池 |
| 准入门槛 | 目标强度 / 段位不匹配 | 进候补，写明原因 |
| 质量线 | 组得分 ≥ **0.62** | 组不成立，人回池 |
| 容量 | 每组不超过该局型上限 | 溢出进候补 |

### 6.3 组长怎么选

不是「最活跃的人」，而是四条件组合：目标强度最高、可用时段 ≥2 个（守时代理）、同校优先、并列时看时段多少。

> 两个代理指标在后台**不得当成事实展示**：守时性（本期无字段，用可用时段代理）、自律度（用问卷关键词推导的强度代理）。后台文案只写「匹配依据」，不写「守时度高」。

### 6.4 匹配理由怎么写

只陈述事实，不做效果承诺。模板里禁止出现「正好」「所以」「难怪」这类把两件事缝成因果的连接词。

- 可以写：你们 6 个人里有 3 个提到「播客」；这组的表达量分布是一个高、五个中
- 不能写：这组里有人正好能接住你的话题

## 7. 数据与隐私

| 项目 | 做法 |
|---|---|
| 数据位置 | 当前版本全部在浏览器 `localStorage`（键 `bushu.v1`），可一键重置 |
| 手机号 | **不采集**。联系走站内码与现场 |
| 场地 | 解锁前不写入 DOM，不是 CSS 隐藏 |
| 同桌信息 | 只给昵称、学校、年级、专业方向、一句自我介绍；不给精确专业与联系方式 |
| 演示身份 | 后台可切换身份，仅用于演示与评审，正式版应移除 |
| 打印件 | 签到码仅在点「打印」后挂载，避免常驻 DOM |

## 8. 视觉与文案规范

### 8.1 字体

| 用途 | 字体 | 说明 |
|---|---|---|
| 标题 | Noto Serif SC（思源宋体）500/600 | 中文标题的骨架来自宋体，不是黑体加粗 |
| 正文 | Noto Sans SC（思源黑体） | 跨平台一致，比系统雅黑干净 |
| 标签/数字 | JetBrains Mono + `tabular-nums` | 等宽数字成列时对得齐 |

> 三条配套规则：宋体标题字重 600（800 会糊）；中文标题字距 0；正文 16.5px / 行高 1.72。

### 8.2 色彩

纸 `#F2EDE3`、墨 `#17140F`、朱红 `#D8351B`，三色为主。松绿只做语义色（成功），面积 ≤5%。2026-10-20 之后停用荧光绿。

### 8.3 文案口径

- 不用感叹号；不用「宝子」「家人」「绝了」
- 不写「保证」「一定」「马上脱单」
- 数字只写能解释的：区间（3–8 人）优于精确值（6 人）

## 9. 技术与部署

| 项目 | 内容 |
|---|---|
| 技术栈 | React 18 + Vite 5，手写 hash 路由；无 UI 框架、无状态库 |
| 样式 | 手写 CSS，token 集中在 `tokens.css`，页面样式按页拆分，最后叠一层 `refine.css` 收质感 |
| 构建 | `npm run build` → `dist/`，当前产物约 1.2MB（JS gzip ≈161KB，CSS gzip ≈22KB） |
| 数据 | `src/data/*` 种子 + `src/lib/store.js` 本地存储；`VERSION` 变更即自动重建 |
| 测试 | `node scripts/match-selftest.mjs`：57 项匹配断言 |
| 发布 | `gh-pages` 分支 + GitHub Pages（不依赖 Actions 权限） |
| 图片 | 2 张 Wikimedia Commons，CC BY-SA 4.0，署名见 `docs/credits.md` |

**目录**

```
src/
  components/   通用组件（按钮/卡片/导航/Marquee/分享条/盲盒…）
  pages/        7 个页面
  lib/          store / api / match / materials / router / format
  data/         种子数据（局型、用户、场次、场地、题库）
  styles/       tokens → base → components → pages → refine
docs/           规格、设计、文案、检查表、图片来源
public/img/     实拍图
```

## 10. 运营手册

### 10.1 每周动作

| 时点 | 动作 | 在哪 |
|---|---|---|
| 周一 | 开下周场次（类型、时间、片区、人数上限、价格） | 后台 / 场次 |
| 周三 | 检查「即将截止」场次，补一条提醒 | 后台 / 告警 |
| 截止后 | 跑匹配 → 看待成组质量 → 发布物料 | 后台 / 匹配工作台 |
| 散场后 | 看回顾与「下次还来吗」，决定是否续开 | 后台 / 回顾 |

### 10.2 指标定义

- **满桌率** = 成桌人数 / 该局型上限
- **成桌率** = 成桌数 / 该场报名人数达标的场次数
- **候补转化** = 候补中最终进桌的比例
- **质量分** = 组得分，低于 0.62 不成桌（门槛，不是 KPI）

## 11. 已知限制与下一步

| # | 限制 | 影响 | 建议 |
|---|---|---|---|
| 1 | 无后端，数据在本机 | 别人报名你收不到；两台手机不同桌 | 接云开发（半天）或轻后端 |
| 2 | 字体走 Google Fonts CDN | 国内可能被阻断，退回系统字体 | 自托管子集（约半小时） |
| 3 | 未做真机触控实测 | 375 宽下的滑动手感未验证 | 真机走查一轮 |
| 4 | 支付与通知缺失 | 只能线下收款、人工通知 | 二阶段 |
| 5 | ICP 与场地授权 | 不能正式对外运营 | 走学校/属地备案 |
| 6 | 演示身份切换 | 正式版不应存在 | 上线前移除 |
